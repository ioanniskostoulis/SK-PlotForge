# Development

PlotForge follows the shell's `PROJECT-STRUCTURE.md`. The frame (menus, tool strip, panels, Terminal, Messages, status bar, welcome screen) comes from the shell; the domain lives in `source/engine` and the domain parts of `source/app`.

| Step | Command |
|---|---|
| Icons and wordmark | Drawn by forge-shell from `forge.config.json` into `build/identity` on every build, preview and package; nothing to commit. `npx forge-shell identity` draws them on their own |
| Shell update | Pin a released archive in `source/` and run `npm install`, following the shell's `UPDATING.md` |

## Running

| Command | Purpose |
|---|---|
| `npm install` | Installs the dependencies and the version hook (`scripts/install-hooks.mjs`) |
| `npm start` | Builds into `build/` and runs the desktop application |
| `npm run web` | Serves the browser preview on `http://127.0.0.1:4278/` |
| `npm run dev` | The browser preview with the desktop frame |

## Checking

| Command | Checks |
|---|---|
| `npm run check` | The TypeScript typecheck |
| `npm test` | The engine tests in `tests/engine`, with the sample files of `tests/fixtures` |
| `npm run test:app` | The interface tests in `tests/app` |
| `npm run test:shell` | Builds, then runs the shell's check of the app (`check-app`: profile, substitutes for shell parts, Settings and Terminal rules) |
| `npm run checks` | All four, in the order CI runs them |

## Versions and releases

The pre-commit hook (`scripts/bump-version.mjs`) raises the patch version in `VERSION`, `package.json` and `package-lock.json` on every commit; a version written into `VERSION` by hand is kept instead. `CHANGELOG.md` gathers changes under `## Unreleased` until a release, when the section takes the version's number.

The workflow `Build desktop apps` (`.github/workflows/build-desktop-apps.yml`, generated by `forge-shell workflows`) runs the checks, builds the macOS disk image and the Windows setup with `npm run dist`, verifies them with `scripts/check-release.mjs`, and publishes both to the release `v<VERSION>`, whose notes are the version's section of `CHANGELOG.md` (`npx forge-shell release-notes` shows them). It runs on pushes to `main`, on `v*` tags and by hand. A push that changes only Markdown files, `documentation/` or `LICENSE` does not start it; run it by hand after such a push when it should publish.
